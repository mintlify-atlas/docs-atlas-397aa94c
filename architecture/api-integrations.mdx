Flatiron Support Troop integrates with three external services at runtime:

| Service | Purpose | Auth |
|---|---|---|
| **Spotify Web API** | Fetch playlist cover art and top-3 tracks per emotion | OAuth 2.0 Client Credentials |
| **OpenWeatherMap** | Current weather at the user's location | API key (query param) |
| **JSON Server (Render)** | Persist and read user feedback comments | None (open) |

All Spotify and weather calls are made inside `src/Components/Emotions.jsx` when the emotion page mounts. Feedback calls are made from `src/Components/Feedback.jsx` on form submit.

---

## 1. Spotify Web API — Token Endpoint

Before any Spotify data fetch can happen, the app must obtain a short-lived **client credentials access token**.

### Endpoint

```
POST https://accounts.spotify.com/api/token
```

### Authentication

The app concatenates `VITE_SPOTIFY_CLIENT_ID` and `VITE_SPOTIFY_CLIENT_SECRET` (Vite environment variables), base64-encodes the result, and sends it as an HTTP Basic Authorization header:

```
Authorization: Basic <base64(client_id:client_secret)>
Content-Type: application/x-www-form-urlencoded
```

### Request Body

```
grant_type=client_credentials
```

### Response Fields Used

| Field | Type | Description |
|---|---|---|
| `access_token` | `string` | Bearer token passed to all subsequent Spotify API calls |
| `expires_in` | `number` | Token lifetime in **seconds** (typically `3600`); multiplied by 1000 for ms comparison |

### Source: `src/Components/spotifyAPI/fetchToken.js`

```js
export async function getSpotifyToken() {
    const client_id = import.meta.env.VITE_SPOTIFY_CLIENT_ID;
    const client_secret = import.meta.env.VITE_SPOTIFY_CLIENT_SECRET;

    if (!client_id || !client_secret) {
        console.error("Missing Spotify Client ID or Secret");
        return;
    }

    const credentials = btoa(`${client_id}:${client_secret}`);

    try {
        const response = await fetch('https://accounts.spotify.com/api/token', {
            method: 'POST',
            headers: {
                'Content-Type': 'application/x-www-form-urlencoded',
                'Authorization': `Basic ${credentials}`
            },
            body: 'grant_type=client_credentials'
        });

        const data = await response.json();
        console.log("Spotify Token Response:", data);

        if (!response.ok) {
            throw new Error(`Failed to fetch token: ${data.error || data.error_description}`);
        }

        return { accessToken: data.access_token, expiresIn: data.expires_in * 1000 };
    } catch (error) {
        console.error("Error fetching Spotify token:", error);
    }
}
```

### Token Caching: `src/Components/spotifyAPI/tokenManager.js`

To avoid requesting a new token on every API call, `tokenManager.js` caches the token in `localStorage` and exposes a single `getValidToken()` function that the rest of the app calls before every Spotify fetch.

```js
import { getSpotifyToken } from './fetchToken.js';

let token = null;
let expirationTime = null;
let tokenPromise = null;

// Rehydrate from localStorage on script load
function loadStoredToken() {
    const storedToken = localStorage.getItem("spotify_access_token");
    const storedExpiration = localStorage.getItem("spotify_token_expiration");

    if (storedToken && storedExpiration) {
        token = storedToken;
        expirationTime = parseInt(storedExpiration, 10);
    }
}

loadStoredToken();

export async function getValidToken() {
    const now = Date.now();

    // Return cached token if still valid
    if (token && now < expirationTime) {
        console.log("Using cached token");
        return token;
    }

    // Deduplicate concurrent requests
    if (tokenPromise) {
        console.log("Waiting for ongoing token request");
        return tokenPromise;
    }

    console.log("Fetching new token...");
    tokenPromise = getSpotifyToken()
        .then(({ accessToken, expiresIn }) => {
            token = accessToken;
            expirationTime = now + expiresIn;

            localStorage.setItem("spotify_access_token", token);
            localStorage.setItem("spotify_token_expiration", expirationTime.toString());

            tokenPromise = null;
            console.log("New token stored:", token);
            return token;
        })
        .catch(error => {
            tokenPromise = null;
            console.error("Token fetch failed:", error);
            throw error;
        });

    return tokenPromise;
}
```

**How the cache works:**

1. On module load, `loadStoredToken()` reads `spotify_access_token` and `spotify_token_expiration` from `localStorage` so a previously fetched token survives a page refresh.
2. `getValidToken()` compares `Date.now()` against `expirationTime`. If the token is still live, it is returned immediately without a network call.
3. If a new token is already being fetched (e.g. two components called `getValidToken()` simultaneously), `tokenPromise` deduplicates the in-flight request — both callers await the same promise.
4. On a successful fetch, the new token and its expiry timestamp are written back to `localStorage`.

<Tip>
  Spotify client credentials tokens are valid for **3600 seconds** (1 hour). The app stores the expiration as an absolute Unix timestamp (`Date.now() + expiresIn`), so token staleness is computed correctly across page reloads.
</Tip>

## 2. Spotify Web API — Playlist Endpoints

Once a valid token is available, `Emotions.jsx` makes two Spotify calls in parallel on mount: one for the playlist's cover image and one for its tracks.

### 2a. Playlist Metadata

```
GET https://api.spotify.com/v1/playlists/:id
```

**Headers:**

```
Authorization: Bearer {access_token}
```

**Response fields used:**

| Field | Description |
|---|---|
| `images[0].url` | URL of the playlist cover art thumbnail |

### 2b. Playlist Tracks

```
GET https://api.spotify.com/v1/playlists/:id/tracks
```

**Headers:**

```
Authorization: Bearer {access_token}
```

**Response fields used (per track item):**

| Field | Description |
|---|---|
| `items[].track.name` | Track title |
| `items[].track.artists[].name` | Artist name(s), joined with `", "` |
| `items[].track.album.images[0].url` | Album art thumbnail (64×64 px displayed) |
| `items[].track.preview_url` | 30-second MP3 preview URL; used as `<audio>` source (may be `null`) |

Only the **first three tracks** are displayed: `emotionPlaylist.slice(0, 3)`.

The playlist `:id` for each emotion is sourced from `pageDataArray` in `src/Components/spotifyAPI/page-array.jsx` (see [Components → Data Modules](/architecture/components)).

### Source: `src/Components/Emotions.jsx` (Spotify fetches)

```jsx
// src/Components/Emotions.jsx (Spotify fetch functions)
import { getValidToken } from './spotifyAPI/tokenManager'

// Fetch playlist cover image
async function fetchSpotifyPlaylistData() {
    const token = await getValidToken();
    const url = `https://api.spotify.com/v1/playlists/${selectPlaylist.id}`;

    try {
        const response = await fetch(url, {
            headers: { 'Authorization': `Bearer ${token}` }
        });

        const data = await response.json();

        if (response.ok) {
            setPlaylistImage(data.images);
        } else {
            console.error(`Error fetching Spotify playlist: ${data.error.message} (Status: ${response.status})`);
        }

    } catch (error) {
        console.error(`Error fetching Spotify playlist: ${error.message}`);
    }
}

// Fetch playlist tracks
async function fetchSpotifyTrackData() {
    const token = await getValidToken();
    const url = `https://api.spotify.com/v1/playlists/${selectPlaylist.id}/tracks`;

    try {
        const response = await fetch(url, {
            headers: { 'Authorization': `Bearer ${token}` }
        });

        const data = await response.json();

        if (response.ok) {
            setEmotionPlaylist(data.items);
        } else {
            console.error(`Error fetching Spotify tracks: ${data.error.message} (Status: ${response.status})`);
        }

    } catch (error) {
        console.error(`Error fetching Spotify tracks: ${error.message}`);
    }
}
```

### Render (tracks excerpt)

```jsx
<ul>
  {emotionPlaylist.slice(0, 3).map((trackItem, index) => (
    <li key={index} className="track">
      <img src={trackItem.track.album.images[0]?.url} width="64" height="64"/>

      <div className='track-info'>
        <h3>{trackItem.track.name}</h3>
        <p>{trackItem.track.artists.map(artist => artist.name).join(', ')}</p>
      </div>

      {trackItem.track.preview_url && (
        <audio controls>
          <source src={trackItem.track.preview_url} type="audio/mpeg" />
          Your browser does not support the audio element.
        </audio>
      )}
    </li>
  ))}
</ul>
```

<Note>
  `preview_url` can be `null` for some tracks (Spotify does not provide previews for all markets or all tracks). The conditional `{trackItem.track.preview_url && ...}` silently omits the `<audio>` player in that case.
</Note>

## 3. OpenWeatherMap — Current Weather

The weather card on each emotion page displays live local conditions using the **OpenWeatherMap Current Weather API**.

### Endpoint

```
GET https://api.openweathermap.org/data/2.5/weather
```

### Query Parameters

| Param | Source | Description |
|---|---|---|
| `lat` | `navigator.geolocation` | User's latitude (from browser Geolocation API) |
| `lon` | `navigator.geolocation` | User's longitude (from browser Geolocation API) |
| `appid` | `import.meta.env.VITE_WEATHER_KEY` | OpenWeatherMap API key (Vite env var) |
| `units` | `"imperial"` | Returns temperatures in °F |

### Response Fields Used

| Field | Description |
|---|---|
| `name` | City name; displayed lowercased (`weatherData.name.toLowerCase()`) |
| `weather[0].description` | Human-readable condition string (e.g. `"light rain"`) |
| `main.temp` | Current temperature in °F; rounded with `Math.round()` |
| `main.feels_like` | Feels-like temperature in °F; rounded with `Math.round()` |

### Geolocation

The weather fetch is gated on `navigator.geolocation`. The browser will prompt the user for location permission the first time the emotion page is visited:

- If permission is **granted**: `getCurrentPosition()` provides `latitude` and `longitude`, which are injected into the fetch URL.
- If permission is **denied** or **unavailable**: `console.error()` is called and `weatherData` remains `{}`. The weather card section is only rendered when `weatherData.name` is truthy, so the card is silently omitted.

### Source: `src/Components/Emotions.jsx` (weather fetch)

```jsx
// src/Components/Emotions.jsx
async function fetchWeatherData() {
    const weatherKey = import.meta.env.VITE_WEATHER_KEY

    if (navigator.geolocation) {
        navigator.geolocation.getCurrentPosition(async (position) => {
            const lat = position.coords.latitude
            const lon = position.coords.longitude

            try {
                const response = await fetch(
                    `https://api.openweathermap.org/data/2.5/weather?lat=${lat}&lon=${lon}&appid=${weatherKey}&units=imperial`
                )
                const data = await response.json();
                setWeatherData(data)

            } catch (error) {
                console.error("Error fetching weather data:", error)
            }

        }, (error) => {
            console.error("Error getting location:", error)
        })

    } else {
        console.error("Geolocation is not supported by this browser")
    }
}
```

### Render

```jsx
{weatherData.name && (
  <div className='weather-report'>
    <h3>weather in {weatherData.name.toLowerCase()}:</h3>
    <p>{weatherData.weather[0].description}</p>
    <p> temp: {Math.round(weatherData.main.temp)} °F </p>
    <p> feels like: {Math.round(weatherData.main.feels_like)} °F</p>
  </div>
)}
```

<Tip>
  The OpenWeatherMap free tier allows **60 calls per minute**. Since `fetchWeatherData` fires once per emotion page load (inside a `useEffect`), staying within this limit is straightforward for a personal-use app. If you extend the app with auto-refresh, add a debounce or interval guard.
</Tip>

## 4. JSON Server — Feedback API

User-submitted feedback comments are persisted to a hosted **JSON Server** instance running on [Render](https://render.com).

### Base URL

```
https://fist-json-server.onrender.com
```

### Endpoint: Submit a Comment

```
POST /responses
```

**Headers:**

```
Content-Type: application/json
```

**Request body:**

```json
{
  "id": 3,
  "text": "Great app!"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | `number` | Derived from `comments.length + 1` at submit time |
| `text` | `string` | The user's feedback string |

**Response:** The created object is echoed back by JSON Server. The app parses the response JSON (`.then(response => response.json())`) but **does not use the returned `data`** — the state update uses the locally constructed `submitComment` object instead (optimistic update).

### Source: `src/Components/Feedback.jsx` (POST fetch)

```jsx
// src/Components/Feedback.jsx
const handleSubmit = (event) => {
  event.preventDefault()

  if (newComment.trim()) {
    const submitComment = {
      id: comments.length + 1,
      text: newComment
    }
    setNewComment("") // reset input field immediately (optimistic)

    fetch('https://fist-json-server.onrender.com/responses', {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(submitComment),
    })
    .then((response) => response.json())
    .then((data) => {
      setComment((prevComments) => [...prevComments, submitComment])
    })
    .catch((error) => console.error("Error submitting comment", error))
  }
}
```

### Optimistic Update Pattern

The input is cleared (`setNewComment("")`) and the comment is appended to the displayed list (`setComment(...)`) before the server confirms success. If the POST fails, the `.catch` logs the error but the comment remains visible in the UI — there is no rollback.

<Note>
  The GET `/responses` endpoint (to load persisted comments on page mount) is present in the source as commented-out code. Currently the `comments` state is pre-seeded with two hard-coded entries and new submissions are only held in memory for the lifetime of the session — a page refresh resets the list to the two seed entries.
</Note>

### No Authentication

The JSON Server instance is publicly accessible with no API key or authentication. Any client that can reach the Render URL can POST to `/responses`.
