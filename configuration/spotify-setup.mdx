## Overview

Flatiron Support Troop fetches mood-matched playlists and track data directly from the Spotify Web API. To do this, the app needs a set of API credentials from a Spotify Developer application. Setup takes about five minutes.

## Create a Spotify Developer App

<Steps>
  <Step title="Log in to the Spotify Developer Dashboard">
    Go to [https://developer.spotify.com/dashboard](https://developer.spotify.com/dashboard) and sign in with your Spotify account. If you don't have one, create a free account first.
  </Step>

  <Step title="Create a new app">
    Click **Create app**. Fill in the required fields:

    | Field | Value |
    |---|---|
    | App name | e.g. `Flatiron Support Troop` |
    | App description | e.g. `Mood-based wellness app` |
    | Redirect URI | `http://localhost:5173` |
    | APIs used | Web API |

    The redirect URI must be a valid URL, but because this app uses the **Client Credentials** flow rather than user-level OAuth, it will never actually be called. `http://localhost:5173` (Vite's default dev port) is a safe choice.

    Click **Save**.
  </Step>

  <Step title="Copy your Client ID and Client Secret">
    Open your newly created app in the dashboard and navigate to **Settings**. You will find your **Client ID** displayed immediately, and a **View client secret** button to reveal the secret.

    Copy both values — you'll need them in the next step.
  </Step>

  <Step title="Add the credentials to your .env file">
    In the project root, open (or create) `.env` and paste in your credentials:

    ```env .env
    VITE_SPOTIFY_CLIENT_ID=your_client_id_here
    VITE_SPOTIFY_CLIENT_SECRET=your_client_secret_here
    ```

    Restart the dev server (`npm run dev`) if it is already running.
  </Step>
</Steps>

## Authentication Flow: Client Credentials

The app uses the [Client Credentials flow](https://developer.spotify.com/documentation/web-api/tutorials/client-credentials-flow) — **not** the Authorization Code (user OAuth) flow. This means:

- No Spotify login prompt is shown to users.
- No user data (listening history, private playlists, playback control) can be accessed.
- Only **public** Spotify resources — such as the five public playlists used by the app — are reachable.

This is the correct choice here because the app only needs to read public playlist and track metadata.

### `fetchToken.js` — Requesting a Token

Every time the app needs a fresh token, `getSpotifyToken()` fires a `POST` to Spotify's token endpoint. The Client ID and Secret are joined with a colon, base64-encoded with `btoa()`, and sent as a `Basic` authorization header alongside `grant_type=client_credentials` in the request body.

```js src/Components/spotifyAPI/fetchToken.js
export async function getSpotifyToken() {
    const client_id = import.meta.env.VITE_SPOTIFY_CLIENT_ID;
    const client_secret = import.meta.env.VITE_SPOTIFY_CLIENT_SECRET;
    
    if (!client_id || !client_secret) {
        console.error("Missing Spotify Client ID or Secret");
        return;
    }

    const credentials = btoa(`${client_id}:${client_secret}`);

    try {
        const response = await fetch('https://accounts.spotify.com/api/token', {
            method: 'POST',
            headers: {
                'Content-Type': 'application/x-www-form-urlencoded',
                'Authorization': `Basic ${credentials}`
            },
            body: 'grant_type=client_credentials'
        });

        const data = await response.json();
        console.log("Spotify Token Response:", data);

        if (!response.ok) {
            throw new Error(`Failed to fetch token: ${data.error || data.error_description}`);
        }

        return { accessToken: data.access_token, expiresIn: data.expires_in * 1000 };
    } catch (error) {
        console.error("Error fetching Spotify token:", error);
    }
}
```

Notice that `expiresIn` is returned as `data.expires_in * 1000` — the raw Spotify response gives a value in **seconds** (typically `3600`), and multiplying by 1000 converts it to milliseconds to match JavaScript's `Date.now()` format used for expiry comparisons.

### `tokenManager.js` — Caching and Reuse

Requesting a new token on every API call would be wasteful (and would quickly exhaust rate limits). `tokenManager.js` wraps `getSpotifyToken()` with a three-layer caching strategy:

```js src/Components/spotifyAPI/tokenManager.js
import { getSpotifyToken } from './fetchToken.js';

let token = null;
let expirationTime = null;
let tokenPromise = null;

// Check if a token exists in localStorage
function loadStoredToken() {
    const storedToken = localStorage.getItem("spotify_access_token");
    const storedExpiration = localStorage.getItem("spotify_token_expiration");

    if (storedToken && storedExpiration) {
        token = storedToken;
        expirationTime = parseInt(storedExpiration, 10);
    }
}

// Call the function to load the token on script execution
loadStoredToken();

export async function getValidToken() {
    const now = Date.now();

    // Use cached token if it's still valid
    if (token && now < expirationTime) {
        console.log("Using cached token");
        return token;
    }

    // Prevent multiple concurrent requests
    if (tokenPromise) {
        console.log("Waiting for ongoing token request");
        return tokenPromise;
    }

    console.log("Fetching new token...");
    tokenPromise = getSpotifyToken()
        .then(({ accessToken, expiresIn }) => {
            token = accessToken;
            expirationTime = now + expiresIn;
            
            // Store token in localStorage
            localStorage.setItem("spotify_access_token", token);
            localStorage.setItem("spotify_token_expiration", expirationTime.toString());

            tokenPromise = null; // Reset promise after completion
            console.log("New token stored:", token);
            return token;
        })
        .catch(error => {
            tokenPromise = null; // Reset on error
            console.error("Token fetch failed:", error);
            throw error;
        });

    return tokenPromise;
}
```

The three layers work as follows:

| Layer | Mechanism | When it applies |
|---|---|---|
| **In-memory cache** | Module-level `token` variable | Fastest path — used when the page is already loaded and the token has not expired |
| **localStorage persistence** | `spotify_access_token` + `spotify_token_expiration` keys | Survives page refreshes; `loadStoredToken()` populates the in-memory variables at module load time |
| **Concurrent-request guard** | `tokenPromise` variable | If two components call `getValidToken()` simultaneously before a token exists, the second call waits on the same `Promise` rather than firing a duplicate network request |

The token expires at `now + expiresIn` (in milliseconds). Since Spotify returns `expires_in: 3600`, the token stays valid for **one hour** after being fetched.

<Note>
  The Client Credentials flow cannot access user-specific Spotify data such as a user's saved tracks, private playlists, or playback control endpoints. All five playlists used by Flatiron Support Troop are public Spotify playlists, so this flow is sufficient.
</Note>
